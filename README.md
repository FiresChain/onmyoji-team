# onmyoji-team

阴阳师对弈竞猜截图识别工具。页面顶部集中设置属性约束、误差与顺序约束；下方左侧粘贴图片，浏览器本地运行 OCR，右侧编辑五位式神的配装参数、查看 JSON，并调用 `onmyoji-api` 编码并下载阵容二维码。不执行御魂配装，不调用付费识别 API。

## 启动

需要 Node.js 22.12+（本地开发使用 Node.js 24）。

```bash
npm ci
npm run dev
```

打开 http://127.0.0.1:5175 。复制图片本身，在页面按 `Ctrl + V` / `⌘ + V`，或点“从剪贴板粘贴”。粘贴后自动识别；新截图会取消上一轮识别。

`predev` / `prebuild` 会执行 `npm run setup`：复制浏览器 OCR 运行文件，并从 Paddle 官方下载两个预训练模型到 `public/runtime/`。后续启动复用这些文件。该目录不提交 Git，首次启动需要联网；图像推理不需要服务器。模型和运行文件较大，移动设备首次初始化可能较慢。

```bash
npm run check  # 表格解析、区域坐标、御魂评分及计算配置测试、TypeScript、生产构建
npm run preview
```

## GitHub Pages 发布

仓库：[FiresChain/onmyoji-team](https://github.com/FiresChain/onmyoji-team)。站点地址：[https://fireschain.org/onmyoji-team/](https://fireschain.org/onmyoji-team/)。`.github/workflows/pages.yml` 在 `main` 推送或手动触发时，使用 Node.js 24 执行 `npm ci`、`npm run check`，再将 `dist/` 发布到 GitHub Pages；OCR 运行库与模型在构建时准备，不提交构建产物。仓库 Pages 的 **Build and deployment → Source** 已设为 **GitHub Actions**（`build_type: workflow`）。发布是否完成以 Actions 的部署结果为准。

正式页面从 `onmyoji-assets.fireschain.org` 读取公开 R2 目录和图片，并使用 `api.fireschain.org` 的阵容编码接口；按发布页面的 Origin 配置 R2 CORS。Vite 使用相对资源路径，供项目子路径部署。

## 数据与职责

- 前端：Vue 3 / TypeScript / Vite。
- OCR：`@paddleocr/paddleocr-js`，PP-OCRv5 mobile 检测与识别模型，Web Worker + WASM 单线程。采用现成模型，没有额外训练。
- SDK 的预构建 Worker 内嵌 ONNX Runtime 1.24.3；运行文件固定使用相同版本，不能单独升级 WASM。
- 式神与御魂目录：`https://onmyoji-assets.fireschain.org/assets/catalog.json`，由 `onmyoji-data` 生成、发布。
- 御魂图片：读取目录中 `libraries.yuhun[*].avatar` 指向的 R2 图片；不内置其他项目的御魂图片，不维护平行的名称与 ID 表。
- 本地开发通过 Vite `/r2` 代理访问该公开 R2 域名，规避新端口未获 CORS 许可的问题。代理只读取公开素材，截图不会发送到代理。
- 正式静态部署时需要为页面 Origin 配置 R2 的 CORS（包括目录和图片），或配置同源素材代理；本工程不修改远程 R2 配置。
- OCR 模型来自 Paddle 官方模型存储；模型不是 onmyoji-data 的游戏素材。
- 截图、OCR 结果仅保留在页面内存中；不上传截图、不写本地持久化、不做遥测。模型下载与 R2 素材读取仍会联网。
- 点击“查看图片”时，将游戏阵容码模板和已保存的计算条件发送到 `POST /onmyoji/v1/team-code/encode`；前端仅把返回的完整 `#TA#` 阵容码画为二维码，不把 JSON 或配置图当作阵容码。

## 第一版输出约定

`schemaVersion: 1` 是本工程的识别草稿版本，**不是阵容码协议，也不是已经可直接传给编码器的请求**。

- `members` 按截图从左到右排列，共五列。布局不足以确定五列时返回空数组和 `warnings`，页面提示更换包含完整五列的截图。
- `panel` 保存界面读数；`percentageUnit: "percentage-points"` 表示 `40` 是 `40%`，`150` 是 `150%`。
- 阵容 JSON 增加 `calculation` 参数草稿；编辑计算设置不会改写 `panel`、式神或御魂识别结果。无效配置会显示 `calculationIssues`，此时禁用阵容 JSON 的复制和二维码生成。
- 未读到或有冲突的数值为 `null`，不会自动补零。
- 式神名优先精确匹配 R2 素材目录；非空 OCR 名称未精确匹配时，从目录中按名称相似度选择最接近的式神，自动填写目录中的 ID 和名称，保留识别原文及最多三个候选，并标记为“模糊匹配，需核对”。即使六字名称被识成五字也不会因此留空；目录不可用或名称未识别时不猜测式神。
- 御魂通过裁剪图标与 R2 素材的颜色、结构相似度比较；只有分项和总分通过要求、首选与第二名有足够差距时，才给出最多三个合格候选。所有候选仍需核对，`catalogId/name` 暂时为 `null`。相似度不是识别准确率或概率。
- 御魂 `status` 为 `candidate` 时有合格候选；有模板但分数不足或前两名过于接近时为 `unrecognized`，`candidates` 为空；无法取得模板或区域时为 `unavailable`。被拒绝的近似结果只保留在识别器内部诊断中，不能直接用于编码。
- `catalogId` 是素材目录 ID；编码适配器校验其在目录中的身份，再转换为 API 使用的式神 ID、`300xxx` 御魂 ID 或独立的两件套效果 ID。API 负责转换底层阵容协议 ID，未识别的式神会阻止编码。
- 技能等级、两件套、主属性和面板取整规则不从截图猜测，列于原识别草稿的 `unresolved`；手动选择的套装与主属性保存在 `calculation`。二维码使用模板保留截图无法确定的字段，不代表这些字段已从截图还原。
- 页面不再提供御魂区域、文字框、裁剪调节、候选分项评分或原始 OCR 调试入口；识别器内部仍保留诊断数据用于测试，颜色与结构匹配算法不变。

## 配装计算设置

页面从全局计算设置开始，下接命中池与截图工作区；粘贴前也可先选配置。识别后默认打开右侧“阵容详情”。点击五个式神头像，在头像下方查看该式神已保存的额外属性、属性上下限和其他配装条件；点击“编辑阵容”，才会打开宽 1120px（小屏自适应）的完整编辑弹窗，并定位到当前选中的式神。`src/components/ManualTargetEditor.vue` 移植了 `onmyoji-yuhun` 原组件的模板、样式和选择器交互：顶部式神槽位，选中式神标题栏，左侧“御魂指定”与右侧“高级定制”。弹窗与选择动画在本仓库独立运行，不依赖另一个仓库的 store、构建产物或运行目录。

- 每位式神默认参与配装，指标为效果命中（`metricId: 2`）。全局“属性约束”固定提供攻击、生命、防御、速度、暴击、暴击伤害、效果抵抗七项，默认全部勾选；命中不生成范围约束。只把勾选的属性写入计算范围，取消勾选保留原编辑值，重新勾选可恢复。切换计算指标不会暗中移除勾选属性。
- “命中式神池”和“命中御魂池”按用户提供的截图预选 26 位式神和 6 种御魂（返魂香、雪幽魂、反枕、魅妖、魍魉之匣、钟灵），每次新开或刷新页面恢复这份预制；仍可手动增删、清空。两个入口与完整阵容编辑共用筛选、搜索和素材卡片：式神按目录中的稀有度筛选，御魂按加成类别筛选。命中池支持多选，切换筛选不会丢失选择，已选名单可单独查看和移除；保存后立即生效，取消或 Esc 不保存修改。当前成员的式神在池内，或当前搭配中有池内的具体御魂（二件或四件）时，其指标自动改为暴击率（`metricId: 8`）；两件套效果和未采用的识别候选不触发。编辑器与成员详情显示生效指标及来源；池子规则生效时不能手动改指标，移出池或更换搭配后恢复原先的手动指标（默认效果命中）。自动规则不修改主属性、范围或目标评分。
- 页面顶部可设置全队误差范围，默认 ±10%，支持 1%／5%／10%／20% 快捷选择及 0～100% 自定义输入。七项属性的编辑范围都按截图值的相对百分比生成上下限，例如攻击 7000 的 ±10% 为 6300～7700，暴击 40% 的 ±10% 为 36%～44%。修改误差会按截图重建参与计算且仍对应原式神的范围，保留御魂、式神、指标及额外属性；已禁用、移除或更换的式神保留原配置。未识别字段不猜数值、不添加限制行。
- “顺序约束”同样提供七项复选框，默认勾选速度、攻击、暴击伤害。仅同时勾选属性约束和顺序约束的属性生效；取消属性约束时，该属性的顺序选项暂不可用但保留选择。按截图数值保持高低顺序，不调整式神槽位；原值相等不强行区分先后。重叠区间以相邻原值中点为界，在原范围内收紧并至少隔开 0.01，例如攻击 7000／7200、±10% 时，最终为 6300～7100／7100.01～7920。未知原值、换式神或动态最高属性与所选保序属性冲突时提示修正；未勾选的保序属性不参与这类检查。
- 保序后的范围显示在式神详情，写入阵容 JSON 和二维码中的属性限制。完整编辑弹窗保留收紧前的范围，取消保序即可恢复；此策略可能排除一部分本来顺序正确的配装，以便仅用游戏已有的上下限字段保证顺序。默认容差和 0.01 分隔不代表游戏面板取整规则。
- 保留五个固定槽位，在完整编辑弹窗内可更换、移除式神，也可点击空槽重新添加。主页面点击空槽只显示未配置提示。式神头像、稀有度和御魂类别来自同一份 R2 素材目录；原识别成员和截图面板保持不变。
- 御魂支持四件套、两件套、两件套效果和剩余散件，可按名称与类别搜索；禁止重复套装、总件数超过六件，以及将首领御魂或两件套效果选为四件套。匹配门槛通过的首选候选会自动填入尚未编辑的空御魂设置，普通御魂按四件套、首领御魂按两件套，仍需玩家核对。异步匹配和目录延迟加载都会补填；手动更换、清空、散件选择及重新匹配时已保存的套装均保留。未识别且尚未指定御魂时阻止导出，不默默生成空套装。
- 计算指标、可选目标评分、2／4／6 号位主属性分别编辑。主属性初始允许任意，通过面板预检后，按钮直接选中实际用于计算的选项，并在每行说明自动排除项。切换指标时按原编辑器行为自动应用推荐主属性，之后可继续多选。切换指标保留属性限制行。
- 高级定制包含最高属性、额外攻击加成／固定攻击／暴击／暴击伤害、属性上下限、全部／未装备范围、仅六星、仅满级以及排除其他已启用阵容占用的御魂。
- 属性限制使用原版的属性下拉框、最低值、最高值和删除按钮，可增删和编辑单边或双边边界。同一属性重复添加会提示修正。百分比输入使用界面数值：例如 `39～41` 表示 `39%～41%`；输入 `0` 是有效限制，留空只表示该侧不限。
- “无需配置御魂”会保留该成员的页面设置，输出 `yuhunConfigEnabled: false` 和空的计算条件；移除式神则将该槽的 `shikigami` 设为 `null`。保留式神但不配置御魂与移除式神是两个不同操作；全部成员不配置御魂时仍可导出。
- 弹窗顶部可编辑阵容名称、计算方式与难度，归属关卡为“对弈竞猜”。难度递补使用 1～100 的整数，强制计算时不使用难度。
- “保存修改”应用弹窗草稿并同步更新 JSON 与头像下方的配置详情；取消编辑、关闭或 Esc 放弃本次编辑。有式神／御魂选择弹窗时，Esc 先关闭最上层选择器。无需配置御魂的式神仍可查看保留的设置，详情会标明其不参与计算。
- “阵容 JSON”中的 `calculation` 包含阵容名称、归属关卡、计算方式和难度，`targets` 按 `slot` 关联原识别成员，包含独立的式神选择、套装、主属性、指标、目标评分、额外属性、范围和筛选条件。`ranges` 沿用 `{stat,min?,max?,percentage}`，百分比是百分点；`extraAttributes` 的百分比按计算器契约除以 100，固定攻击保持原值，并用 `extraAttributesPercentageUnit: "ratio"` 单独标明。
- 清空、重新识别或粘贴新截图保留顶部全局选择，重新建立该截图的成员配装设置。当前不跨刷新保存。

这是可编辑的配装参数草稿，尚未连接御魂库存或执行配装。它保留素材目录 ID、未确认状态及截图来源，经独立适配器转换后才传给 encode；不能把目标评分理解为“最接近截图”的误差目标。

`calculation.reproduction` 保存 `tolerancePercent`、`constraintStats`、`orderStats`；顺序约束按后两者的交集执行。`targets[].ranges` 仅包含勾选属性实际用于计算的上下限，包含适用的保序或卸装补偿结果。编码适配器仅发送最终范围，不向游戏协议增加这些全局选择字段。

`calculation.hitMetricPools` 记录两个池的素材 ID。导出适配器只将生效的 `metricId` 写入游戏协议，不发送池子名单。命中池与其他全局选择一样保留到本次页面关闭或刷新。

### 面板预检与主属性收紧

保存和导出前，会按六星 40 级标准面板、御魂主属性、已确认的套装增益和额外属性做本地预检。基础资料来自网易官方式神录的数据接口，覆盖当前素材目录的 278 项；可觉醒式神采用觉醒状态，SP、UR、N、呱和素材采用原生状态。资料仅包含式神种类、养成状态和公共属性，不包含账号、式神实例或御魂标识。缺少数据或来源存在未解决差异时标为“未预检”，不会据此禁用配置。预检采用保守下界，通过预检不代表库存中一定存在可用配装。

- 对仅六星御魂，枚举用户允许的 2／4／6 号位主属性，每个阶段最多 100 种组合。仅满级时使用 +15 主属性；不限等级时使用 +0 下界，排除最低面板已超过上限的组合，将剩余组合按位置合并为实际导出的主属性选项。游戏协议只能表达各位置的可选集合，所以合并后的组合数可能大于通过下界检查的组合数。编辑器显示实际导出选项；原始允许范围在用户未手动修改时仍保留，放宽约束可自动恢复。点击某个主属性以当前看到的集合为起点修改，点击“任意”重新允许全部合法属性，再按面板自动筛选。
- “仅六星”和“仅满级”默认同时勾选。六星 +15 全部组合都超出上限时，先尝试下述 1／3／5 号位卸装补偿；补偿不能解决时，再取消“仅满级”，保留“仅六星”，从原始允许集合重新按六星 +0 下界筛选。六星 +0 仍全部超限时，才进一步取消“仅六星”。每阶段重新计算，不沿用上一阶段排除的主属性。截图目标和原始编辑草稿保留，界面与阵容码显示实际生效的条件；通过下界检查不代表已找到可用配装。
- 卸装补偿仅针对六星 +15 的固定主属性：1 号位攻击 486、3 号位防御 104、5 号位生命 2052；攻击还会乘以用户设置的额外攻击百分比。对已有的对应属性上限增加这一贡献，下限不变，然后重新筛选 2／4／6 主属性。选择需要卸下位置最少、相对扩展幅度最小的方案，最多提醒两个位置，且剩余件数必须足够容纳全部指定套装；明确要求四件套加两件套时不会生成卸装建议。成功时保留六星、满级，显示原上限与计算上限，以及计算后的卸装提醒。
- 卸装补偿只是放宽计算条件，未计入被卸御魂的副属性，也不能指定计算结果中哪个位置一定属于散件。卸下后必须重新核对面板、套装及队伍次序，尤其可能掉到原属性下限以下，或改变原有属性高低顺序。提示不代表已经找到库存配装，也不保证卸下后达到截图目标。原上限仍在编辑弹窗保留；详情、JSON 和阵容码使用实际扩展后的上限。
- 六星 +0 数据来自两个本地账号导出中 9,863 件未强化御魂的交叉核对，11 类主属性的观察值均一致：固定攻击 81、生命 342、防御 14，速度 12，暴伤 14%，其余可选百分比主属性 10%。只保留通用属性值，不打包账号或御魂实例数据。这是以“强化不降低主属性”为前提的经验下界模型，并非官方完整星级、等级成长表。六星 +15 常量沿用现有计算器口径。
- 指定四件套包含一次对应的二件套属性增益；其余未确定的副属性和套装贡献不猜测。未限制六星时，只检查式神基础、固有奖励、必带套装及额外属性是否已经超限，保留原允许主属性，不猜测缺失的低星下界。玩家手动取消“仅六星”时也不会被重新勾上。未知增益或基础资料不足时会标明未预检。
- 只有上述不依赖御魂星级、等级的属性下界已经超过上限，或者保序后属性区间为空，才继续判定冲突：保留槽位与身份，输出 `yuhunConfigEnabled: false`，在阵容码里设置“不配置御魂”。六星满级模式没有组合时会先自动放宽，不能直接视为所有御魂都无解。
- 自动放宽不会覆盖原始草稿；修改误差或约束后重新计算，如果六星满级重新通过必要条件预检，两项自动恢复原选择。玩家手动取消的选项不会被自动勾回。自动放宽时若手动勾选一项，以当前可见的两个开关值为起点修改，避免另一项隐藏的原值改变用户选择。
- 修改误差、御魂、主属性或约束后会重新预检；冲突消除便恢复配置。玩家手动勾选“不配置御魂”的成员不会被自动启用。
- 顺序约束只处理最终参与配置的成员及选中的属性，禁配成员不会继续压缩其他成员的范围。卸装补偿不能扩大正在保序的属性上限，但未选择保序的生命、防御等属性仍可补偿。保序产生的空区间按成员报告冲突；全局未勾选的范围值不会阻塞导出。
- `calculationPrechecks` 保存每位式神的预检状态与原因；`calculation.targets` 是实际用于编码的结果。诊断字段不发送给编码 API。

预检不扫描玩家库存，不启动耗时的御魂组合搜索；它不能控制游戏内计算器的运行时间。此功能只修改 `onmyoji-team`。编码保留模板的觉醒状态，因此模板的养成状态仍需与上述标准面板对应。

### 基础面板来源与口径

`src/data/shikigami-base-panels.json` 保存六星 40 级的八项基础属性及独立的觉醒奖励。数据取自[官方式神录](https://yys.163.com/shishen/index.html)实际使用的 `get_hero_attr` 和 `get_hero_skill` 接口，保留小数精度。官方 `critPower` 是额外暴击伤害，入库时加 1；命中、抵抗和暴击等比例统一以 `0.3 = 30%` 保存。这些数据随前端构建打包，识图与预检时不请求官方接口，也不调用付费 API。

官方裸面板包含部分式神的固定觉醒奖励，不能直接作为御魂百分比的分母。数据将成长基础值 `base` 与固定奖励 `innate` 分开，例如大天狗的攻击按 `3135.6 × (1 + 10%觉醒 + 御魂攻击加成) + 御魂固定攻击` 计算，避免将觉醒奖励重复放大。速度和暴击等固定奖励直接相加。命中与抵抗使用官方裸属性，包含思金神的天生 30% 抵抗。

蝉冰雪女的官方数据与本地已验证的历史基础值在攻击、防御上存在差异，暂存为待核验数据，跳过面板预检。其他成员照常处理；新目录 ID 没有对应数据时也跳过，不自动猜测。此处的“未预检”与配装范围已证明冲突不同：只有后者才会在阵容码中设置“不配置御魂”。

本次以 189 种已验证的六星 40 级基础值交叉核对，拆开觉醒奖励后 188 种一致，只有蝉冰雪女存在上述差异；结果记录在 `src/data/shikigami-base-panels-audit.json`。其余数据以官方接口为来源，未声称已逐种用账号样本验证。

维护者更新面板时，先更新公开式神目录，再运行：

```bash
npm run data:update
# 默认读取相邻 onmyoji-data/catalogs/shikigami.json，也可指定同格式的公开目录：
npm run data:update -- --catalog /path/to/shikigami.json
```

更新脚本限 3 个并发、单次请求 15 秒、整次更新 8 分钟；接口失败、未知稀有度或无法解释的固定觉醒奖励会终止更新，保留原数据。它不会读取私人账号导出。已有官方响应缓存时，可去掉 `--fetch`，通过 `--awake-dir`、`--native-dir`、`--skill-dir` 指定目录离线重建；`--reference` 可选传入只含通用基础值的 schema 1 参考表进行核对。联网更新直接生成新表，不保存原响应缓存。数据更新后运行 `npm run check`。

## 阵容二维码

右侧面板右上角“查看图片”使用内置阵容码模板调用阵容编码 API，再把返回的完整 `#TA#...` 文本生成黑白 PNG 二维码，无需额外输入阵容码。支持预览、原始大小和下载，二维码保留四个模块的白边，避免装饰影响扫描。每次使用已保存的设置；保存新配置或重新识别会取消过期请求并清除旧二维码。

内置模板是一份已在游戏中导入成功、含五个式神槽位的阵容码。编码仅更新阵容名称和五位式神的选择、配装条件，并显式指定式神 **六星 40 级**；阴阳师、游戏场景、对应槽位的觉醒／技能及未知协议字段保留模板值。截图无法确定这些字段，生成后请在游戏中核对。计算方式和难度属于本工具设置，不写入游戏码。主属性“任意”编码为该位置完整的合法属性集合；未设置评分时保留模板已有的 `null` 或 `0`，清除已设评分时写为 `null`；没有范围及额外属性时使用游戏导出的空值格式。

编码支持具体四件套、具体两件套和两件套效果，以及指标、目标评分、主属性、最高属性、额外加成和双边属性限制。当前尚未确认单边区间、仅未装备、排除其他阵容占用及多组具体两件套的协议表达；选用这些设置时会明确提示，不能静默丢弃约束。范围百分比保持百分点（`100` 表示 `100%`），额外百分比加成保持比例（`0.2` 表示 `20%`）。

API 地址通过 `VITE_ONMYOJI_API_URL` 配置，默认 `https://api.fireschain.org`。新接口未部署时，请在 `onmyoji-api` 运行 `npm run dev -- --local --port 8787`，并在本工程的 `.env.development.local` 设置 `VITE_ONMYOJI_API_URL=http://127.0.0.1:8787`。开发与生产环境均使用同一份内置阵容码模板。HTTP 404 会提示接口未部署，不回退到配置图或伪阵容码。

## 御魂识别算法

御魂区域横坐标参考属性数字列，纵坐标参考“御魂效果”文字；缺少该文字时使用行间距估算。这是表格布局推算，尚未使用图标轮廓检测，所以数字中心与图标中心错位时会误匹配。区域和匹配诊断仅在识别器内部保留，页面不显示调试框。

匹配使用 24×24 像素图，以推算区域为基础，在宽高各 ±12% 的范围内按 6% 间隔搜索 5×5 个中心，再尝试截图的 0.85 / 1 / 1.15 倍、R2 原图居中正方形的 1 / 0.85 / 0.7 倍裁切。每个御魂优先保存通过条件的最高分组合，没有合格组合时保留最高分用于解释拒绝原因。

当前评分纯本地运行，无需训练模型：

- 40% 结构分：灰度归一化相关系数，负相关记为 0；零相关直接为 0，不再映射成 0.5。任一侧灰度标准差小于 2（0–255 标度）时结构分为 0，避免近乎平坦的图块产生虚假相关。
- 40% 颜色分：HSV 软分桶直方图的 Bhattacharyya 系数，色相环形插值，低饱和度像素按中性色明度处理。
- 20% 像素分：`max(0, 1 − RGB平均绝对误差 / 128)`，用于约束对齐后的具体颜色。

三项都在 0–1 范围。仅比较中央圆形内、截图和模板 alpha 均 ≥ 160 的像素；有效像素不足 50 个或覆盖不到模板有效区的 90% 时拒绝。初版合格门槛是总分 ≥ 0.70、结构 ≥ 0.35、颜色 ≥ 0.50，第一、第二个合格候选分差 ≥ 0.035。门槛集中在 `src/soul-scoring.ts`；这些是针对当前样图与负例检查的保守启发式值，尚未用多玩家、多设备数据集校准。不合格候选不会自动填入御魂套装，用户可在阵容编辑中手动选择。

## 适用范围与验证

优先测试游戏的横屏“阵容详情”表格：五列式神、八行属性、底部御魂图标。完整截图和单独裁剪的表格均可；尚不支持拼接表格、遮挡和其他游戏界面。R2 原图与游戏图标可能在裁剪和装饰上有差异，所以御魂候选必须人工核对。

解析和几何测试覆盖五列对应、百分比单位、缺失/冲突数值、缩放位移、未匹配式神、目录不可用，以及原截图到处理图的偏移换算、区域缩放和边界裁剪。御魂评分另有异色、低饱和、透明覆盖、无相关、空白与候选歧义检查。构建通过不代表 OCR 准确率已验证；实际字体、图片压缩、移动浏览器表现需用真实截图测试。
